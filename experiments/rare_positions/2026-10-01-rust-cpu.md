# Rust odds CPU optimization — 2026-10-01

## Status

Goal: about 25% less full-request CPU on four cores, preserving nonzero coverage.
Baseline: current Rust master `e9cce7dcf570ba53b2d489add5569db9eedd45db`.
The retained portable candidate measures **20.22% less CPU in 28 cold pairs**
and **22.01% less CPU in 56 warm pairs**, with no lost estimates in either cohort.
Wall latency decreased 18.62% and 19.72%, respectively. The 25% target remains
short; these figures include reallocated search work.

Production has four Intel Xeon E5-2697 cores at 2.7GHz. There is no production
access. Per the user's instruction, assume these portable source improvements
apply there; exact percentages may differ. Measurements here use the local ARM
Mac. No instruction-set-specific optimization or ARM PGO is recommended.
The user authorized shipping this validated candidate after reviewing results.

Unrelated pre-existing changes in search.rs, tilt.rs and the README's late-gap
section are excluded from the isolated build and archived patch. No database
changes or live server changes. Builds use at most four jobs; requests are serial
with four estimator workers. CPU means summed user+system process time, not an
instantaneous utilization percentage. Wall means full HTTP request latency.

## Retained changes

- Hoist endpoint CDF rows, outcome factors and compiled domain bounds out of
  repeated outcome checks. Use i64 gain intervals, preserving allowed outcomes.
- Build constant CDF tails once in original outcome order; retain almost-one
  floating-point residues. Handle negative and oversized caps directly.
- Bound rank-DP updates to nonzero support and skip deterministic 0/1 terms.
  Tests compare every DP bit with the original arithmetic.
- Prepare rank-guidance chance tables lazily for cardinality sampling. Reuse
  unchanged suffix rows. Negative and out-of-table caps use the original formula.
  Skip unused non-cardinality weights. The existing guide memory admission limit
  is unchanged: smaller storage does not admit additional plans.
- Use generation-marked direct mass arrays for point lattices up to 65,536
  states, retaining hash insertion order and every floating-point addition.
  Larger events keep the original sparse path. Dense scratch is at most 1MiB
  per concurrently built event on this host.
- Prepare blocker caps and remove redundant overflow/cardinality checks only
  after the existing invariants guarantee them. Compact simple sampler fields;
  preserve fixture RNG order, including forced-result compaction.
- Borrow existing mixture keys and use inline small keys for fresh draws,
  allocating an owned key only when a root first appears. Longer keys spill.
- Store conditional-score indices separately, use an exact 256-bin starting
  index, then refine with the original CDF. Preserve score and RNG results.
- Compare leading points/wins as integers; tied/head-to-head cases retain the
  complete phase comparator. Make private RNG cursor bounds visible to the
  compiler with wrapping/clamped arithmetic, preserving the Go RNG sequence.

Samples, weights, support, proof rules and probability acceptance gates remain
unchanged. No rank-specific searches were introduced.

### Funding feedback

The old rare-tail budget was 35% of elapsed native work. Faster kernels shrink
that allowance and can remove estimates even when every sample is identical.
The retained default is **45% of the shorter elapsed native time**, reallocating
some savings to rare-cell searches. All reported total CPU/latency includes this
work. Explicit `RUST_ODDS_RARE_TAIL_BUDGET_FRACTION` still overrides the default.
No extra absolute-time allowance is assumed.

Timing-based admission remains variable. One intermediate 16498/318/rank5 loss
at seed1669 had identical pilots; more training was admitted, leaving insufficient
confirmation funding. Final cold validation includes that seed. Zero losses in
these cohorts are evidence, not a universal guarantee for every future request.

## R31 — Discretizing Poisson means

The user suggested rounding uncertain Poisson means. The experiment instead
kept the original target means/CDFs while grouping lookup tables by a0.01 mean
bucket. A rounded lookup must be corrected against the actual CDF. First,
nearest-grid indices with two-way correction were56.69% more CPU/52.72% more wall
in12 MC-heavy pairs: rejected.

A second version builds exact indices, then stores the per-bin **minimum** index
among actual means in each bucket. Every shared index is at most the original
index, so the existing forward scan finds exactly the original score. No extra
per-draw backward check, no rounded target distribution and no changed RNG draws.
Arc tables shrink fixture layout; a same-binary control separates sharing from
that layout change. Zero and mean>32 paths remain unchanged.

| Comparison | Pairs | CPU change | Wall change | Gains/losses |
|---|---:|---:|---:|---:|
| Conservative grid/layout vs retained R30, MC-heavy groups | 12 | −13.37% | −10.61% | 0/0 |
| Same candidate vs retained R30, all seven snapshots | 28 | −1.31% | −1.31% | 1/1 |
| Grid0.01 vs grid0, identical smaller-layout binary | 14 | −2.18% | −1.74% | 0/0 |

Rare-heavy snapshots increased CPU2.46–4.07%; other snapshots decreased
10.67–19.35%. Lost cell:16498/318/rank5 at seed1669, due wall-time admission.
**Do not enable this version.** Source reverted, experimental patch retained.
Boundary and fixed-RNG tests passed, including tiny positive means and means>32.

### Rounding the actual means

A separate literal test rounds each unplayed fixture's home/away mean to the
nearest0.01. Existing zeros stay zero; positive means stay positive. The same
retained R30 executable runs original and rounded JSON requests, alternating
arms at seeds1987/1993 across all seven snapshots (14 pairs). No source change
or table reuse is mixed into this control.

CPU13144.046 →13297.405ms (**+1.17%**); wall5398.501 →5460.752ms (**+1.15%**).
Coverage2 gained/4 lost cell-runs. Losses are all16498/seed1993:16/rank12,
318/rank4,5/rank18,8/rank20. Largest absolute existing-estimate difference is
0.003123 (0.3123 percentage points). Among695 paired nonzero estimates below
1e-6, the median rounded/original ratio is1.005; individual ratios range0.00254
through461.8. Those are adaptive estimator outputs, not ground-truth probability
errors: changing means also changes sampled candidates, proposal fitting and
acceptance, and wall-time funding varies. This test cannot separate those effects
or establish accuracy of the approximate model.

Rounding means alone does not save meaningful CPU: distributions are already
constructed once per request. Sharing full rounded distributions is a distinct
future cache experiment. The actual mean approximation is **not enabled**, since
this test offers no speed benefit and loses estimates under the coverage goal.
Individual goal masses multiply across constrained fixtures, so model changes
can compound for rare events even when each mean changes only slightly.

## Reproduction

The exact portable patch excludes unrelated workspace edits. From the repository:

```bash
python3 experiments/rare_positions/benchmark_rust_cpu.py \
  --candidate-patch experiments/rare_positions/2026-10-01-cpu-optimization/portable.patch.gz \
  --seeds 1669,1847,1861,1867 \
  --output /tmp/golaberto-cpu
```

The underlying paired request command is:

```bash
python3 experiments/rare_positions/benchmark_propagated_joint.py \
  --baseline /tmp/baseline --candidate /tmp/candidate \
  --production-candidate --seeds 1669,1847,1861,1867 \
  --output /tmp/golaberto-cold
```

Use `--persistent` for the warm protocol. The build helper extracts isolated
baseline/candidate trees, clears compiler flags, builds with `-j4`, and records
host, compiler, request and executable hashes. No production access is required.
Normal production build remains `cargo build --release --locked -j4` in odds-rust.

The experimental `poisson-grid.patch.gz` applies after the portable patch.
Build separately and compare **against the portable candidate**, with
`--flag RUST_ODDS_POISSON_LOOKUP_STEP=0.01`. For the sharing-only ablation use the
same grid binary for both arms, baseline step0 and candidate step0.01. It is not
part of the retained production source.

Reproduce the actual-mean sensitivity test:

```bash
python3 experiments/rare_positions/experiment_poisson_mean_grid.py \
  --binary /tmp/candidate --step 0.01 --seeds 1987,1993 \
  --output /tmp/golaberto-rounded-means
```

This deliberately compares different probability models. It does not mutate
saved snapshots or the database.
