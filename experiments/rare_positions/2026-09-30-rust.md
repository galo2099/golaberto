# Native Rust estimator: full-request comparison

## Result

The current matched-point-pool pipeline has been implemented in `odds-rust/`
on branch `codex/rare-position-rust`, starting from Go commit `8d9f2136`.
It runs independently of Go and preserves the request/response odds contract.

Across **100 paired full requests** using **four cores**, total estimator time
fell from **104.13 seconds to 53.81 seconds**, a **48.3% reduction** / **1.94×
aggregate throughput equivalent**. The median individual paired speedup was
**1.71×**. Every measured Rust request was under one second; the maximum was
929 ms. These are measurements on the local ARM64 macOS machine, not a promise
for another server.

| Saved input | Median Go | Median Rust | Median paired speedup |
|---|---:|---:|---:|
| 16498 / 44eabb47 | 1,299 ms | 810 ms | 1.69× |
| 16653 / earlier 2d1c1d6f | 1,089 ms | 665 ms | 1.62× |
| 16653 / current 71d4fea8 | 1,093 ms | 661 ms | 1.64× |
| 16982 / 9327edcd | 873 ms | 292 ms | 2.99× |
| 16983 / 43969b02 | 870 ms | 287 ms | 3.03× |

There are **five snapshots of four distinct groups**, including two versions
of group 16653. The table reports medians of 20 runs per input; the last column
is the median of paired ratios, which need not equal the ratio of the medians.

## What was preserved

- 20,000-season initial scout and game importance calculation.
- 100,000-season pool in ten fixed batches, exact team-point PMFs, actual-finish
  matched pooling, shrinkage, jackknife errors, and matrix balancing.
- Point bounds, joint cap/floor impossibility proofs, and bounded constructive
  and neighborhood reachability searches.
- Exact point-event conditioning, backward sampling, wins-aware rank screen,
  suffix-guided importance proposals, and likelihood-ratio correction.
- Guided pilots, extra conditional batches, point tilts, independent
  confirmations, extreme-tilt crosschecks, proved/undecided gap rescues,
  recycled proof work, and cross-team witnesses.
- Directional peer rescue, constraint-based peer scheduling, propagated
  fixture domains, forced-fixture compaction, and reduced score simulation.
- Reachability metadata, zero-hit upper bounds, unchanged acceptance gates,
  and rollback if the final matrix cannot be reconciled.

No sample budget or precision gate was relaxed to obtain these timings.
The current 35% relative-SE acceptance threshold remains in place. The older
CEM-only paths and optional million-draw deep experiments were not selected
in this comparison and are not part of this port.

`reference/2026-09-30-hundredfold/reference.json`. It includes well-observed
5M-MC cells, independently repeated importance estimates, and certified
impossibilities. Its provisional and undecided cells are excluded from scoring.
It is a reference with uncertainty, not exact probability truth.

but its trajectories can differ because Go creates campaigns in randomized

game-importance difference across these pairs was 0.029 on its 0–1 scale.
The finishing-position quality table above does not score game importance.

## Differential and exhaustive checks

- Go RNG floats and the complete 1,000-season joint point/rank scout match a
  saved Go oracle exactly for group 16653, seed 808.
- The initial 100,000-season differential pool check had identical rank counts
  and maximum probability difference below 1e-15.
- Of 360 short conditional-kernel checks on the current 16653 input, 348
  matched within tight numerical tolerances. The remaining 12 checks are
  low-ESS last-position proposals for teams 457, 68, and 69. Native floating
  arithmetic and DP accumulation alter their trajectories. These noisy pilot
  results are not automatically accepted as estimates; full-request quality
  was evaluated separately.
- Exhaustive enumeration of a four-team, six-fixture league verifies that
  conditional events include every rank hit, their masses are correct, cap
  and floor proofs never exclude feasible relaxations, and propagated domains
  retain every rank hit.
- Weighted estimates agree with exact enumeration within sampling uncertainty.
  Tests also cover the unchanged acceptance gate, structural-zero balancing,
  Rails JSON nulls, plain-MC fallback uncertainty, and packed-point overflow.

All ten Rust tests pass; `cargo check`, formatting, and the full Go test suite
pass. The local HTTP smoke check covers valid odds requests, CLI/HTTP response
equality, matrix normalization, health, invalid requests, and Content-Length.
After the final fallback/overflow checks, seed 808 was rerun on all five
snapshots: Rust responses remained identical to the benchmark build.

Correct float parsing matters: `serde_json` is built with `float_roundtrip` so
request fixture powers retain their exact binary values. The legacy random
tiebreak comparator uses a translated Go PDQsort, and simulation streams use
the translated Go RNG. Standard Rust sorting cannot safely substitute for that
nontransitive comparator.

## Profiling and optimizations

A five-second native CPU sample of repeated complete Rust requests identified
conditional event construction, rank proposals, and backward sampling as the
main active stacks. Waiting for parallel workers also appears in the sample
and is not counted as useful CPU work.

The rewrite uses flat campaign arrays, dense joint point/rank counts, cached
Poisson CDFs, shared suffix distributions, and integer-key DP maps. Two further
changes were measured before the final 100-pair run:

1. Single-team backward transitions use direct arrays rather than hash lookups.
2. Event construction reserves its next layer and stops immediately once the
   existing state limit is exceeded. Such events are discarded by both
   implementations, so completing the discarded layer cannot improve a result.

For current 16653 / seed 808, stage instrumentation before and after these
changes reduced extra-search wall time from roughly 264 ms to 182 ms. Full
request quality was subsequently checked across all five inputs.

The stronger speedups in 16982/16983 reflect their relatively small remaining
rare-search cost: most of their work is the plain simulation and pool stage,
where the flat Rust representation helps most.

## Recommendation

Keep the Rust implementation as the candidate for an `/odds` deployment trial:
it preserves measured quality and nearly halves aggregate time on this suite.
The CLI and local HTTP adapter are available. Rails routing remains unchanged,
and Go still supplies ratings and other endpoints. A deployment should compare
performance on its own CPU and explicitly accept the documented seed-specific
variation in the four group-16498 tails.
